# Recorded assumptions and decisions

Gaps that do not require credentials or a business choice are resolved here.
Each decision names repository or supplied-specification evidence so it can be
revisited without reconstructing intent.

| ID | Decision | Evidence and consequence |
|---|---|---|
| A-001 | The source workspace is `./ocgpu` relative to the supplied workspace. | The request explicitly names that path; `Cargo.toml` and all generated paths use it as their root. |
| A-002 | Rust 1.97.1 is the release toolchain; public shipping crates retain MSRV 1.85.0. | The supplied version-baseline table names both versions. `rust-toolchain.toml` pins releases and workspace package metadata records the MSRV. |
| A-003 | Repository metadata omits a repository URL until one is supplied. | No hosting organization or URL was provided. Omitting the field avoids publishing a false provenance locator. |
| A-004 | Ordinary builds, C packaging, the CLI, and offline coverage reporting must not discover or invoke a GPU SDK. | The supplied SDK-free contract forbids `nvcc`, `hipcc`, `hipconfig`, bindgen/libclang, vendor headers, and import libraries. The repository-owned absence preflight, shipping-graph checks, and import-table audits enforce it while permitting installed driver runtimes. |
| A-005 | A static `ocgpu` archive still dynamically resolves the installed vendor runtime. | The supplied decision says CUDA Driver static linking is unavailable and Windows HIP SDK components do not support the proposed vendor-static mode. No `vendor-static` feature exists. |
| A-006 | Vendor snapshots decide existence and ABI; pinned Rust crates are independent ecosystem-coverage oracles only. | The supplied oracle hierarchy explicitly gives official vendor inventories authority. Exact pins exist only in unpublished `ocgpu-oracle`. |
| A-007 | General HIP and Windows HIP remain independent inventories and metrics. | The supplied baselines are HIP 7.14.60850 generally and Windows HIP SDK 7.2.0. The Windows AMD hardware workflow explicitly selects the Windows file. |
| A-008 | Committed snapshots and classifications, not live websites or Cargo registry contents, are the reproducible normal-build baseline. | The supplied automated-coverage design permits online fetching only in a maintainer update job. `ocgpu-oracle check` is offline after dependencies are present. |
| A-009 | Every oracle item receives one exclusive reviewed classification and a substantive reason; coverage scores remain separate. | The supplied coverage section rejects a blended percentage and lists eight accounting states. The catalog validator rejects missing, duplicate, orphan, and short reasons. |
| A-010 | The installed CLI embeds deterministic raw-DEFLATE coverage JSON. | The supplied CLI requirement calls for compressed committed coverage independent of source/network/registry data. The oracle generator fixes the schema, minified bytes, compressor, level, and freshness check. |
| A-011 | ABI v1 supports only 64-bit Windows and Linux targets. | The supplied CI section explicitly excludes 32-bit targets and adds aarch64 Linux after layout validation. Target masks contain only those three triples. |
| A-012 | Device-code compilation and runtime compilers remain out of the core project. | The supplied device-code section requires applications to provide PTX/cubin/fatbin or HIP/AMDGPU code objects and reserves RTC support for a later separate extension. |
| A-013 | Hardware tests are opt-in, bounded, and never run on a workstation serving an interactive display. | The user requires avoiding display crashes, disconnects, shutdowns, and reboots at all costs. The manual workflow requires dedicated labels, explicit acknowledgement, a 15-minute bound, and the prohibitions in `docs/operations.md`. |
| A-014 | Missing optional symbols are capability results, never panics; loaded libraries live until process exit. | The supplied loader design requires structured errors/null entries and process-lifetime handles. This preserves all issued function and GPU handle validity. |
| A-015 | The CC0 claim covers independently authored and generated project material, not every compiled byte or any vendor runtime. | The supplied provenance section requires this precise boundary. `LICENSES/CC0-1.0.txt`, third-party notices, and `docs/provenance.md` record it. |
| A-016 | CUDA 13.3 Update 1 / API 13030 is the sole production CUDA denominator for ABI v1; CUDA 13.4 Developer Preview is excluded. | The supplied baseline labels 13.4 non-production. Preview declarations may inform a future review but do not affect current exports or metrics. |
| A-017 | Unified flat C leaves take an explicit backend first and never select global state; raw flat leaves remain vendor-shaped. | Backend-bound coexistence is a core ABI requirement. The generated header gates the convenience surface behind `OCGPU_ENABLE_FLAT_C_EXPORTS` and documents missing-symbol sentinels. |
| A-018 | Cargo's internal C library target is `ocgpu_capi`, while cargo-c installs the public library, import library, header, and pkg-config name `ocgpu`. | Distinct internal names prevent the MSVC PDB collision with the `ocgpu` CLI; `package.metadata.capi.library.name` preserves the public ABI/package contract. |
| A-019 | The first initialization attempt for each backend fixes its result and library path for the process lifetime. | Process-lifetime function pointers and GPU handles make reload/path replacement unsafe. Per-backend one-time cells preserve deterministic coexistence without a global selected backend. |
| A-020 | Proc-address lookup is fail-closed and direct-only unless exact version, flags, variant, and full normalized ABI evidence match. | CUDA typedef metadata is committed from `cudaTypedefs.h`; version alternatives or similar names are not ABI proof. Direct symbol fallback remains available only for exact reviewed names. |
| A-021 | When an authoritative source genuinely omits an ordinary-pointer nullability contract, the final fact is `unspecified_by_source`; mutable pointer syntax never implies output or non-null. | Clang can prove constness but not semantic direction/nullability. Callbacks require explicit reviewed nullable/non-null evidence and may not use the source-unspecified state. |
| A-022 | Explicit absolute-path loading is an unsafe Rust-only ABI v1 feature; C uses secure default discovery. | The caller must trust the library/dependency closure, constructors, exact vendor ABI, and file identity. A future C path override would require append-only version negotiation. |
| A-023 | A real vendor function wins when an alias spelling collides with a different ABI; such aliases are accounted as unrepresentable rather than sharing a C slot. | One deterministic `ocgpuCu*` identifier cannot safely denote two calling signatures. Exact macro aliases with one ABI-identical target may share reviewed runtime resolution. |
| A-024 | The CycloneDX release SBOM contains only non-dev dependencies reachable from shipping roots; the complete lock graph is separately scope-labelled for repository maintenance. | This avoids implying that oracle/codegen tools are compiled into release artifacts or that third-party components inherit the authored CC0 document license. |
| A-025 | Tagged releases attach attested Rust `.crate` source archives, while crates.io publication remains a separately authorized, credentialed, dependency-ordered operation. | The repository has no registry credential or registry publication evidence; distinguishing archive construction from publication keeps provenance claims testable. |
| A-026 | HIP 5, HIP 6, and HIP 7 are distinct runtime ABI profiles behind one validated common API; older profiles/versions never inherit current HIP 7 raw-callability from a matching export name alone. | The requested application binary must run at the installed capability level without linking an SDK. Secure candidate/profile binding plus runtime-version verification selects the profile; HIP 5/6 and supported HIP 7 versions below the platform raw baseline expose only reviewed compatible raw slots and report the remainder as `profile_unavailable`. |
